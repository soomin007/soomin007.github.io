# soomin007.github.io

내가 만든 게임을 한곳에 모아 두는 허브 사이트다. 인스타그램 프로필에 걸어 둔 링크가 이 사이트로 연결된다.

라이브 주소는 https://soomin007.github.io/ 이다.

홈 화면은 게임 상점처럼 생겼다. 위쪽에서 대표 게임이 캐러셀로 넘어가고, 그 아래에 모든 게임이 카드로 깔린다.
카드를 누르면 그 게임만을 위한 소개 페이지(`g/<id>/`)로 이동한다. 소개 페이지는 게임 본편의 색과 실제 데이터를 쓰고,
본편 규칙을 줄인 맛보기까지 담은 HTML 파일 하나로 되어 있다. 페이지마다 OG 썸네일과 제목이 따로 있어서,
링크를 어디에 공유해도 그 게임의 모습으로 보인다.

## 파일 구조

```
index.html        홈 뼈대 (OG 태그, 폰트, 홈과 폴백 상세 컨테이너)
g/<id>/           게임별 소개 페이지. 다섯 게임 모두 있다
styles.css        홈과 폴백 상세 페이지의 스타일
games.js          게임 데이터 배열. 카드, 캐러셀, 폴백 상세가 모두 이 파일을 읽는다
app.js            games.js 로 홈을 그리고, 라우팅과 기기별 정렬을 맡는다
timepick.js       홈의 "몇 분 있으세요?" 질문
pick/             시간과 기기를 묻고 게임 하나를 권하는 설문 페이지 (첫 시도로 남겨 둠)
assets/           게임별 카드 이미지 (1232x706 webp)
assets/feat/      캐러셀 전용 이미지 (1680x800 webp)
assets/shots/     소개 페이지에 쓰는 스크린샷
og.png            허브 공유 썸네일 (1200x630)
icon.png          파비콘 (256x256)
known-issues.md   반복해서 빠지기 쉬운 함정 모음. 코드를 고치기 전에 먼저 읽는다
DESIGN_HANDOFF.md 디자인 도구에 넘기는 브리프
session_logs/     작업 세션마다 남기는 기록
```

빌드 과정은 없다. HTML, CSS, JS 정적 파일뿐이라서 push 하면 GitHub Pages 에 바로 반영된다.

## 화면과 기기에 따라 달라지는 동작

화면 폭은 375px 부터 1920px 까지 맞춰 두었다. 폰에서는 캐러셀 화살표를 숨기고, 스와이프나 아래쪽 점으로 넘기게 했다.

터치 기기로 들어오면 터치만으로 할 수 있는 게임(`mobile: true`)이 앞쪽에 정렬된다.
키보드가 있어야 하는 게임에는 "키보드 필요" 배지가 붙는다. 인스타그램 프로필에는 주소를 쿼리 없이 그대로 걸면 되고,
예전에 쓰던 `?from=...` 이 붙은 링크로 들어와도 문제없이 열린다.

홈의 "몇 분 있으세요?" 질문에서 시간을 고르면, 그 시간과 기기에 맞는 게임 하나가 맨 앞 카드로 올라온다.

카드를 누르면 그 게임의 소개 페이지로 이동한다. 예전 주소 형식인 `#g/<id>` 로 들어오면 소개 페이지로 자동으로 넘겨 준다.
아직 소개 페이지가 없는 게임(`page` 필드가 비어 있는 게임)은 홈 안에 내장된 폴백 상세 화면을 보여 준다.

사용자가 시스템에서 동작 줄이기(`prefers-reduced-motion`)를 켜 두었다면 캐러셀 자동 회전과 장식 애니메이션이 꺼진다.

## 새 게임을 올리는 방법

먼저 게임의 대표 스크린샷이나 키아트로 카드 이미지를 만든다. 16:9 로 잘라 아래처럼 변환한다.

```
ffmpeg -y -i <원본> -vf "crop=...,scale=1232:706" -c:v libwebp -q:v 82 assets/<게임id>.webp
```

캐러셀 전용 이미지(`assets/feat/<게임id>.webp`, 1680x800)도 함께 만들어 `imgFeat` 에 연결하는 것이 좋다.
만드는 규칙은 known-issues #10 에 있고, 이 이미지가 없으면 카드 이미지가 대신 쓰인다.

다음으로 `games.js` 의 `GAMES` 배열에 게임을 추가한다. 각 필드의 뜻은 파일 맨 위 주석에 정리해 두었다.
`page` 를 비워 두면 폴백 상세 화면이 나오므로, 여기까지만 해도 배포할 수 있다.
화면에 보이는 문구는 합쇼체로 쓰고, em dash(U+2014)는 쓰지 않는다. `facts` 와 스크린샷 설명에는 확인된 사실만 적고,
플레이 시간 같은 수치를 짐작으로 채우지 않는다.

여유가 있으면 전용 소개 페이지(`g/<게임id>/index.html`)도 만든다. 기존 다섯 페이지 가운데 분위기가 비슷한 것을 복사해서
시작하면 되는데, 그 전에 known-issues.md 를 먼저 읽어야 한다. 게임 본편의 색과 실제 데이터로 내용을 채우고,
전용 `og.png`(1200x630)도 함께 만든 뒤 games.js 의 `page` 필드에 연결한다.

`GAMES` 배열의 순서가 데스크톱 화면에 보이는 순서다. 처음 온 사람이 가장 쉽게 빠져들 만한 게임을 맨 앞에 둔다.

## 남은 일

다른 게임을 itch.io 에 올리게 되면 games.js 의 itch 칸을 채운다. 다만 itch 업로드가 꼭 필요한 것은 아니다.
허브는 GitHub Pages 링크만으로도 충분히 돌아간다.

커스텀 도메인을 사게 되면 이 저장소의 Settings → Pages → Custom domain 에 등록한다.
그러면 다른 프로젝트 페이지들도 모두 새 도메인 아래로 옮겨 가고, 기존 주소는 GitHub 이 새 주소로 넘겨 준다.
