# 2026-11-11 세션 로그

## 세션 1 (적자생존 내리기와 남은 일 정리)

### 요약
사용자가 적자생존을 허브에 굳이 넣고 싶지 않다고 해서, 허브와 섬과 소개 페이지에서 모두 내렸다. 섬은 땅 다섯 개가 됐다.
옛 섬이 찍혀 있던 섬 입구 그림과 링크 미리보기 그림을 새로 만들고, 미뤄 두었던 폰 피처드 캐러셀의 가독성 문제를 고쳤다.
남아 있던 작업 트리 세 개를 정리했고, 더 넣을 만한 것은 조사해서 제안만 했다.

### 주요 변경
- `games.js`: 적자생존 항목을 지웠다. Be the Bee 소개의 "한 줄로"가 320, 360 폭에서 꺾여 `~` 로 묶었다.
- `world/index.html`: 적자생존 땅 설정, 일지 연결, 그 땅에만 쓰이던 `buildWild` 와 `buildFence` 를 지웠다. 섬은 games.js 를 읽어
  땅을 나누므로 다섯 칸으로 다시 나뉜다. 링크 미리보기를 `world/og.png`(1200x630 PNG)로 바꾸고 twitter:card 를 더했다.
- `g/selection-pressure/`, 적자생존 그림 다섯 장(캡슐, 피처드, 장면 셋): 지웠다. 게임 자체(soomin007/selection-pressure)의 배포는 그대로다.
- `assets/island.webp`(섬 입구 그림), `world/og.png`, `og.png`(허브 미리보기): 새 섬을 이름표 없이 찍어 다시 만들었다.
  옛 `og.png` 에는 적자생존 화면과 자간을 넓힌 영문 꼬리표가 있었고 충전이 필요해!가 빠져 있었다.
- `styles.css`: 폰(640px 이하) 피처드는 글을 그림 아래 바탕색 칸에 둔다. 글 칸 최소 높이는 폭마다 잰 값(173, 205, 233px)이다.
- `tools/measure-feat.cjs`: 피처드 슬라이드별 글 칸 높이를 폭마다 재는 도구.
- `known-issues.md` #29, `DESIGN_HANDOFF.md` 현재 상태(다섯 게임, 폰 피처드 배치, 섬 미리보기 그림).
- 적자생존 저장소 README(83b086a): 지운 허브 소개 페이지 링크를 뺐다.
- 로컬 정리: `.claude/worktrees` 의 일지 작업 트리 세 개와 로컬 브랜치 둘을 지웠다(커밋은 모두 main 에 들어가 있었다).

### 결정 사항
- 적자생존 소개 페이지는 목록에서만 빼지 않고 지웠다. 링크가 끊긴 페이지가 남으면 검색으로 들어온 사람이 길을 잃는다. 기록은 git 에 있다.
- 섬 입구 그림과 미리보기 그림에는 이름표를 넣지 않았다. 작게 줄면 글씨가 흐려지는데, 이번 일의 발단이 흐린 이름표였다.
  섬 페이지 미리보기는 카카오톡 같은 곳의 호환을 생각해 WebP 대신 PNG 로 했다(다른 소개 페이지의 og.png 와 같다).
- 폰 피처드: 그림이 게임마다 달라 글이 안전하게 놓일 자리를 보장할 수 없어서 글을 그림 밖으로 뺐다. 자동으로 넘어가는 캐러셀이라
  높이가 슬라이드마다 같아야 해서, 잰 값으로 최소 높이를 정했다(측정 도구로 다시 잴 수 있다).
- 충전이 필요해!의 상태는 live 로 둔다. 11월 4일 이후 개발을 멈췄지만 엔딩까지 있는 완성된 판이라, "개발 보류" 표시는 맞지 않는다.
- 과제전에 낼 주소는 섬(https://soomin007.github.io/world/)이다. 과제로 만든 작품이 섬이고, 오른쪽 위 "목록으로 보기"로 허브에 갈 수 있다.
- 확인: 섬 이름표 검사(폰, PC 모두 통과, 이름표 6개), 허브 페이지 9개 콘솔 오류와 가로 넘침 없음, check-design 걸린 곳 없음,
  check-text 홈과 섬 네 폭 모두 0곳. 배포(5686441) 성공 뒤 라이브에서 적자생존 페이지와 그림이 404, 새 그림 두 장이 로컬과 같음을 확인했다.

### 미해결 / 다음 할 일
- 사용자 결정 대기: 더 넣을 것 제안(섬 작품 설명 패널, WebGL 이 안 되는 컴퓨터용 안내, 오프라인 전시용 자동 둘러보기, 감상 남기기).
- 카카오톡에 예전에 공유한 링크는 미리보기가 한동안 옛 그림으로 남을 수 있다(카카오 쪽 캐시).

## 세션 2 (섬 소개 창과 WebGL 안내)

### 요약
사용자가 앞 세션에서 제안한 것 가운데 섬 작품 설명과 WebGL 이 안 되는 컴퓨터용 안내를 둘 다 만들라고 해서, 섬 페이지에 넣고 배포했다(c57f146).
작품 설명은 코드와 기록으로 확인되는 사실로만 초안을 썼다. 만든 이유를 적은 둘째 문단은 사용자가 자기 말로 고칠 차례다.

### 주요 변경
- `world/index.html`: 머리글에 "섬 소개" 버튼과 소개 창(`#about`)을 만들었다. 마우스와 키보드 설명(`.for-pc`)은 터치 기기에서 감춘다.
  WebGL 을 쓸 수 없으면 섬 그림과 이유, 목록으로 보기와 섬 소개 버튼이 있는 안내 화면(`#fail`)이 뜨고,
  three.js 를 받지 못하거나 준비 도중 오류가 나면 다시 불러오기와 목록으로 보기가 뜬다. 8초가 지나도 섬이 안 뜨면 로딩 문구 아래에 목록 링크가 나온다.
  이 처리는 모듈 앞의 일반 스크립트(`islandFail`)에 있고, 모듈은 렌더러 생성만 try 로 감쌌다.
- 같은 파일: 버튼이 셋이 되면서 320px 에서 머리글이 4px 넘쳐, 380px 이하에서는 버튼 사이를 10px 로 줄였다. 머리글 버튼은 누르는 자리를 위아래로 8px씩 넓혔다.
- `README.md`, `DESIGN_HANDOFF.md`: 소개 창과 안내 화면 설명. 핸드오프 첫머리의 "지금 6개"를 5개로 고쳤다.
- `known-issues.md` #30: 3D 페이지가 WebGL 없이 열리면 로딩 문구에서 멈춘다.

### 결정 사항
- 소개 창은 머리글 오른쪽 버튼으로 연다. 웹 3D 체험들이 정보 버튼을 모서리에 두는 방식을 따랐고, 첫 방문에 저절로 띄우지는 않았다.
  섬이 솟아오르는 첫 장면을 글로 가리게 되고, 폰으로 들어온 사람에게 글부터 내미는 셈이라서다.
- 소개 글의 근거: 섬이 하는 일은 코드에서, 만든 이유는 중간 과제 README("어떻게 하면 사람들이 제 게임을 해 보고 싶어질까")와
  11월 2일 세션 로그(전시관과 지도를 둘 다 만든 뒤 지도를 고른 일, 갤럭시 2 의 월드맵, 육각 타일의 출처)에서 가져왔다.
  게임 개수처럼 바뀌는 수치는 쓰지 않았고, 만든 사람은 사이트의 다른 곳처럼 soomin007 로 적었다.
- 안내 화면에 섬 그림(`assets/island.webp`)을 넣었다. 과제전 심사에 쓰일 컴퓨터를 알 수 없어서, 3D 가 안 되는 곳에서도 작품의 모습은 보이게 했다.
- 확인: 소개 창(열고 닫을 때 초점, 열린 동안 섬의 Esc 와 화살표 키가 막히는지, 바깥을 누르면 닫히는지), WebGL 을 끈 브라우저,
  three.js 요청 차단, 느린 연결을 320, 360, 390, 1440 폭에서 검사해 모두 통과했다. 섬 이름표 검사, 페이지 9개 점검,
  check-design, 섬 check-text 도 통과했다. 배포 뒤 라이브 `world/index.html` 이 커밋과 같고, 라이브에서 소개 창과 WebGL 을 끈 안내 화면이 뜨는 것을 확인했다.
- Pages 빌드 기록이 새 커밋 대신 앞 커밋(014c5ac)으로 찍혀서 새 run 을 기다리느라 10분을 썼다. 라이브 파일은 이미 새 커밋이었다(known-issues #25 보강).

### 미해결 / 다음 할 일
- 사용자: 소개 글 둘째 문단(만든 이유)을 자기 말로 고친다. 실명이나 과목 표기를 바꾸려면 `#about` 의 `sheet__lead` 한 줄을 고치면 된다.
- `hall/` 도 three.js 를 쓰지만 안내 화면이 없다. 검색에서 뺀 첫 스케치라 미뤘다.
